# Исправление проблемы "Connection Abort" при загрузке больших файлов

## Проблема

Сайт падает с ошибкой "Connection Abort" через ~10 минут при загрузке больших файлов.

## Причины

1. **Недостаточные таймауты** - таймауты были установлены на 4 часа, но для очень больших файлов при медленном интернете этого может быть недостаточно
2. **Файлы загружаются в память** - если `FILE_UPLOAD_MAX_MEMORY_SIZE` слишком большой, Django пытается загрузить файл в память, что приводит к падению
3. **Буферизация в nginx** - если буферизация не отключена, nginx может пытаться загрузить весь файл в память

## Решение

### 1. Увеличены таймауты до 8 часов

**Nginx (`infra/nginx/nginx.conf`):**
```nginx
proxy_connect_timeout 28800s;  # 8 часов
proxy_send_timeout 28800s;     # 8 часов
proxy_read_timeout 28800s;     # 8 часов
send_timeout 28800s;           # 8 часов
```

**Gunicorn (`backend/gunicorn_config.py`):**
```python
timeout = 28800  # 8 часов (в секундах)
graceful_timeout = 28800  # 8 часов
```

### 2. Проверка настроек Django

Убедитесь, что в `backend/config/settings.py` установлено:

```python
# ВАЖНО: Файлы больше 100MB должны писаться на диск, а не в память
FILE_UPLOAD_MAX_MEMORY_SIZE = 100 * 1024 * 1024  # 100 MB

# Максимальный размер всего запроса
DATA_UPLOAD_MAX_MEMORY_SIZE = 200 * 1024 * 1024 * 1024  # 200 GB
```

### 3. Проверка настроек Nginx

Убедитесь, что в `infra/nginx/nginx.conf` установлено:

```nginx
# Отключаем буферизацию для streaming
proxy_buffering off;
proxy_request_buffering off;

# Увеличиваем таймауты
proxy_read_timeout 28800s;  # 8 часов
```

## Применение изменений

### На сервере выполните:

```bash
# 1. Скопируйте обновленную конфигурацию nginx
sudo cp ~/sofa-marketplace/infra/nginx/nginx.conf /etc/nginx/sites-available/sofa-api
# или обновите существующий конфиг вручную

# 2. Проверьте конфигурацию nginx
sudo nginx -t

# 3. Перезагрузите nginx
sudo systemctl reload nginx

# 4. Перезапустите gunicorn
sudo systemctl restart sofa-backend

# 5. Проверьте статус сервисов
sudo systemctl status nginx
sudo systemctl status sofa-backend
```

## Проверка работы

### Мониторинг логов во время загрузки:

```bash
# Логи nginx
sudo tail -f /var/log/nginx/error.log
sudo tail -f /var/log/nginx/access.log

# Логи gunicorn
sudo journalctl -u sofa-backend -f

# Проверка использования памяти (не должна расти до 200GB)
watch -n 1 free -h
```

### Что должно происходить:

1. **Nginx** принимает файл и передает его в Gunicorn через proxy (streaming, без буферизации)
2. **Django** получает файл и, так как он больше 100MB, сразу пишет его на диск (не в память)
3. **S3 Storage** (если настроен) получает файл с диска и загружает в S3
4. Временный файл удаляется после загрузки в S3

## Дополнительные рекомендации

### Если проблема все еще возникает:

1. **Проверьте место на диске:**
   ```bash
   df -h
   ```
   Убедитесь, что есть достаточно места (минимум 200GB + запас)

2. **Проверьте системные лимиты:**
   ```bash
   ulimit -a
   cat /proc/$(pgrep nginx | head -1)/limits
   ```

3. **Увеличьте таймауты еще больше** (если необходимо):
   - В nginx: до 43200s (12 часов)
   - В gunicorn: до 43200 (12 часов)

4. **Используйте chunked upload** на фронтенде для загрузки файлов по частям

5. **Рассмотрите прямую загрузку в S3** через presigned URLs (обход Django)

## Важные замечания

1. **Время загрузки:** Загрузка 200GB файла может занять **несколько часов** даже при хорошем интернете
2. **Мониторинг:** Следите за использованием памяти и диска во время загрузки
3. **Таймауты:** 8 часов должно быть достаточно для большинства случаев, но при очень медленном интернете может потребоваться больше
4. **S3:** Если используется S3, файлы должны загружаться напрямую в S3, а не на локальный диск

## Устранение проблем

### Проблема: Все еще падает через 10 минут

**Решение:**
- Проверьте, что изменения применены (перезапущены nginx и gunicorn)
- Проверьте логи на наличие других ошибок
- Убедитесь, что `proxy_buffering off;` установлен
- Убедитесь, что `FILE_UPLOAD_MAX_MEMORY_SIZE = 100MB` (не больше!)

### Проблема: Нехватка памяти

**Решение:**
- Убедитесь, что `FILE_UPLOAD_MAX_MEMORY_SIZE = 100MB`
- Убедитесь, что `proxy_buffering off;` установлен
- Проверьте, что файлы пишутся на диск, а не в память

### Проблема: Медленная загрузка

**Решение:**
- Это нормально для больших файлов
- Используйте chunked upload для лучшего UX
- Рассмотрите прямую загрузку в S3
