# 🔧 Исправление CORS ошибки для подписанных URL

Если вы получаете ошибку CORS при использовании подписанных URL:

```
Access to fetch at 'https://s3.ru1.storage.beget.cloud/...' from origin 'https://vizhub.art'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present
```

## ✅ Решение: Настройка CORS в Beget

### Шаг 1: Откройте настройки бакета в Beget

1. Войдите в панель управления Beget
2. Откройте ваше S3 хранилище
3. Перейдите в раздел **"Настройки"** → **"Настройки CORS"**

### Шаг 2: Добавьте CORS правило для endpoint URL

Нажмите **"Добавить"** и заполните:

- **Origin**: `https://vizhub.art` (ваш домен)
  - Или `*` для всех доменов (менее безопасно, но проще)
- **Разрешенные HTTP-методы**:

  - ✅ **GET** (обязательно) - для загрузки файлов
  - ✅ **HEAD** (рекомендуется) - для получения метаданных
  - ⚠️ **OPTIONS** не доступен в панели Beget, но обычно обрабатывается автоматически сервером S3 для preflight запросов

- **Разрешенные заголовки**: `*` (или конкретные заголовки, если нужно)

- **Время кэширования CORS**: `3600` (1 час)

**Важно:** В панели Beget доступны только методы GET, PUT, DELETE, POST, HEAD. Метод OPTIONS не отображается в списке, но обычно обрабатывается автоматически сервером S3 для CORS preflight запросов.

### Шаг 3: Важно - добавьте CORS для endpoint URL

**Критически важно:** При использовании подписанных URL файлы загружаются с endpoint URL (`s3.ru1.storage.beget.cloud`), а не с custom domain.

Убедитесь, что CORS настроен для:

- ✅ Custom domain (если используете): `604ac302c572-joyful-valeriy.s3.ru1.storage.beget.cloud`
- ✅ Endpoint URL (обязательно для подписанных URL): `s3.ru1.storage.beget.cloud`

### Шаг 4: Проверьте настройки

После добавления CORS правила:

1. Сохраните изменения
2. Подождите несколько минут (настройки могут применяться с задержкой)
3. Попробуйте загрузить файл снова

## 🔍 Проверка CORS

Откройте консоль браузера (F12) → вкладка Network и проверьте:

1. **Preflight запрос (OPTIONS)** должен возвращать статус 200 или 204
   - Если OPTIONS запрос отсутствует, это нормально - браузер может использовать кэш
2. В заголовках ответа GET запроса должны быть:
   - `Access-Control-Allow-Origin: https://vizhub.art` (или `*`)
   - `Access-Control-Allow-Methods: GET, HEAD` (может включать другие методы)
   - `Access-Control-Allow-Headers: *` (или конкретные заголовки)

**Примечание:**

- Метод OPTIONS не доступен для выбора в панели Beget, но обычно обрабатывается автоматически сервером S3 для preflight запросов
- Для подписанных URL достаточно методов GET и HEAD
- Если CORS все еще не работает, попробуйте использовать `*` для Origin (менее безопасно, но работает)

## 🚨 Если проблема сохраняется

### Вариант 1: Используйте wildcard для Origin

Временно используйте `*` для Origin в CORS настройках (менее безопасно, но работает):

- **Origin**: `*`

### Вариант 2: Проверьте правильность endpoint URL

Убедитесь, что в `.env` указан правильный endpoint URL:

```bash
AWS_S3_ENDPOINT_URL=https://s3.ru1.storage.beget.cloud
```

Или проверьте в панели Beget раздел **"Реквизиты доступа"** → **"URL"**

### Вариант 3: Переключитесь на публичный доступ (временно)

Если CORS не работает, можно временно переключиться на публичный доступ:

```bash
# В файле .env
S3_FILE_ACCESS_MODE=public
```

И включите публичную политику в настройках бакета Beget.

## 📝 Дополнительная информация

- CORS настройки применяются на уровне бакета
- Изменения могут применяться с задержкой до нескольких минут
- Для подписанных URL обязательно нужен CORS для endpoint URL
- Custom domain и endpoint URL могут иметь разные CORS настройки
