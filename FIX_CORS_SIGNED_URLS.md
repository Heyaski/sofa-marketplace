# 🔧 Исправление CORS ошибки для подписанных URL

Если вы получаете ошибку CORS при использовании подписанных URL:

```
Access to fetch at 'https://s3.ru1.storage.beget.cloud/...' from origin 'https://vizhub.art'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present
```

## ✅ Решение: Настройка CORS в Beget

Согласно [официальной документации Beget](https://beget.com/ru/kb/manual/obektnoe-hranilishche-s3-v-beget), CORS настраивается на уровне бакета и применяется ко всем запросам, включая подписанные URL.

### Шаг 1: Откройте настройки бакета в Beget

1. Войдите в [панель управления Beget](https://beget.com/ru/kb/manual/obektnoe-hranilishche-s3-v-beget)
2. Перейдите в раздел **"Объектное хранилище S3"**
3. Выберите ваш бакет из списка
4. Перейдите на вкладку **"Настройки"** выбранного бакета
5. Найдите раздел **"CORS"** или **"Настройки CORS"** и нажмите **"Изменить"** или **"Добавить"**

### Шаг 2: Добавьте CORS правило

Заполните следующие параметры согласно официальной документации Beget:

- **Allowed Origins (Разрешенные источники)**:

  - Укажите `https://vizhub.pro` (ваш домен, БЕЗ слеша в конце!)
  - ⚠️ **Важно:** Убедитесь, что указан правильный домен (не `vizhub.art`, а `vizhub.pro`)
  - Или `*` для всех доменов (менее безопасно, но работает для тестирования)
  - ⚠️ **Важно:** `https://vizhub.art` и `https://www.vizhub.art` считаются разными доменами - добавьте оба, если используете оба варианта

- **Allowed Methods (Разрешенные HTTP-методы)**:

  - ✅ **GET** (обязательно) - для загрузки файлов
  - ✅ **HEAD** (рекомендуется) - для получения метаданных
  - ⚠️ **OPTIONS** обрабатывается автоматически сервером S3 для preflight запросов (не нужно указывать вручную)

- **Allowed Headers (Разрешенные заголовки)**:

  - Укажите `*` для разрешения всех заголовков
  - Или конкретные заголовки, если требуется ограничение

- **Expose Headers (Открытые заголовки)**:

  - Можно оставить пустым или указать `ETag`, `Content-Length` и другие заголовки, которые нужны клиенту

- **Max Age Seconds (Максимальный возраст)**:
  - Укажите `3600` (1 час) - время кэширования результатов preflight-запросов

### Шаг 3: Сохраните настройки

После заполнения всех полей:

1. Нажмите **"Сохранить"** или **"Применить"**
2. Подождите несколько минут (настройки могут применяться с задержкой до 10-15 минут)
3. Попробуйте загрузить файл снова

**Важно:** CORS настройки применяются на уровне бакета и работают для всех запросов к бакету, включая подписанные URL. Не нужно настраивать CORS отдельно для endpoint URL и custom domain - настройки применяются ко всем запросам к бакету.

## 🔍 Проверка CORS

Откройте консоль браузера (F12) → вкладка Network и проверьте:

1. **Preflight запрос (OPTIONS)** должен возвращать статус 200 или 204
   - Если OPTIONS запрос отсутствует, это нормально - браузер может использовать кэш
2. В заголовках ответа GET запроса должны быть:
   - `Access-Control-Allow-Origin: https://vizhub.art` (или `*`)
   - `Access-Control-Allow-Methods: GET, HEAD` (может включать другие методы)
   - `Access-Control-Allow-Headers: *` (или конкретные заголовки)

**Примечание:**

- Метод OPTIONS не доступен для выбора в панели Beget, но обычно обрабатывается автоматически сервером S3 для preflight запросов
- Для подписанных URL достаточно методов GET и HEAD
- Если CORS все еще не работает, попробуйте использовать `*` для Origin (менее безопасно, но работает)

## 🚨 Если проблема сохраняется

### ⚠️ Важно: Проверьте настройки CORS в Beget

Если вы получаете ошибку CORS даже после настройки, проверьте следующее:

1. **Убедитесь, что CORS настроен для правильного домена:**

   - В панели Beget откройте **"Настройки"** → **"Настройки CORS"**
   - Проверьте, что в поле **Origin** указан именно `https://vizhub.art` (без слеша в конце!)
   - Или используйте `*` для всех доменов (менее безопасно, но работает)

2. **Проверьте точность указания Origin:**

   - Убедитесь, что Origin указан точно: `https://vizhub.art` (БЕЗ слеша в конце!)
   - Если используете `www.vizhub.art`, добавьте отдельное правило для него
   - Попробуйте временно использовать `*` для проверки, работает ли CORS вообще

3. **Проверьте формат подписанных URL:**
   - Подписанные URL могут использовать endpoint URL: `https://s3.ru1.storage.beget.cloud/...`
   - CORS настройки применяются ко всем запросам к бакету, независимо от формата URL

### Вариант 1: Используйте wildcard для Origin

Временно используйте `*` для Origin в CORS настройках (менее безопасно, но работает):

- **Origin**: `*`
- **Разрешенные HTTP-методы**: GET, HEAD
- **Разрешенные заголовки**: `*`
- **Время кэширования CORS**: `3600`

### Вариант 2: Проверьте правильность endpoint URL

Убедитесь, что в `.env` указан правильный endpoint URL:

```bash
AWS_S3_ENDPOINT_URL=https://s3.ru1.storage.beget.cloud
```

Или проверьте в панели Beget раздел **"Реквизиты доступа"** → **"URL"**

**Важно:** Endpoint URL должен совпадать с доменом в подписанных URL!

### Вариант 3: Проверьте формат подписанных URL

Проверьте, что подписанные URL генерируются правильно:

```
https://s3.ru1.storage.beget.cloud/bucket-name/path/to/file.glb?X-Amz-Algorithm=...
```

**Примечание:** CORS настройки работают независимо от формата URL (endpoint URL или custom domain), так как настройки применяются на уровне бакета.

### Вариант 4: Переключитесь на публичный доступ (временно)

Если CORS не работает, можно временно переключиться на публичный доступ:

```bash
# В файле .env
S3_FILE_ACCESS_MODE=public
```

И включите публичную политику в настройках бакета Beget.

**Примечание:** После переключения на публичный доступ перезапустите Django сервер.

## 🔧 Диагностика проблемы

Если проблема сохраняется, выполните следующие проверки:

1. **Проверьте URL в ошибке браузера:**

   - Откройте консоль браузера (F12)
   - Найдите запрос к файлу .glb
   - Скопируйте полный URL из ошибки
   - Убедитесь, что URL начинается с `https://s3.ru1.storage.beget.cloud`

2. **Проверьте заголовки ответа:**

   - В консоли браузера откройте вкладку **Network**
   - Найдите запрос к файлу .glb
   - Откройте вкладку **Headers**
   - Проверьте заголовки ответа:
     - Должен быть `Access-Control-Allow-Origin: https://vizhub.art` (или `*`)
     - Если заголовка нет, значит CORS не настроен правильно

3. **Проверьте настройки CORS в Beget:**

   - Войдите в панель Beget
   - Откройте ваше S3 хранилище
   - Перейдите в **"Настройки"** → **"Настройки CORS"**
   - Убедитесь, что есть правило с Origin `https://vizhub.art` или `*`
   - Убедитесь, что указаны методы GET и HEAD

4. **Проверьте логи Django:**
   - Проверьте логи Django на наличие ошибок генерации подписанных URL
   - Убедитесь, что подписанные URL генерируются правильно

## 📝 Дополнительная информация

Согласно [официальной документации Beget](https://beget.com/ru/kb/manual/obektnoe-hranilishche-s3-v-beget):

- CORS настройки применяются на уровне бакета и работают для всех запросов к бакету
- Изменения могут применяться с задержкой до нескольких минут (иногда до 10-15 минут)
- CORS работает для всех типов запросов, включая подписанные URL (presigned URLs)
- Метод OPTIONS обрабатывается автоматически сервером S3 для preflight запросов
- Если CORS настроен правильно, но все равно не работает:
  - Попробуйте очистить кэш браузера или использовать режим инкогнито
  - Проверьте, что Origin указан точно (без слеша в конце, с правильным протоколом)
  - Временно используйте `*` для Origin, чтобы проверить, работает ли CORS вообще
