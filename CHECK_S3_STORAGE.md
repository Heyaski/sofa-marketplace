# Проверка настройки S3 хранилища Beget

## Проблема

Файлы должны загружаться в облачное хранилище Beget (S3), а не на локальный диск сервера.

## Проверка настроек

### 1. Проверьте файл `.env` в директории `backend/`

Убедитесь, что файл существует и содержит следующие настройки:

```bash
# Активация S3 хранилища (ОБЯЗАТЕЛЬНО должно быть 1)
USE_S3_STORAGE=1

# Реквизиты доступа из панели Beget
AWS_ACCESS_KEY_ID=your_access_key_here
AWS_SECRET_ACCESS_KEY=your_secret_key_here
AWS_STORAGE_BUCKET_NAME=your-bucket-name

# Endpoint URL (из раздела "Реквизиты доступа" -> "URL")
AWS_S3_ENDPOINT_URL=https://s3.beget.com

# Публичный URL бакета (из раздела "Реквизиты доступа" -> "Публичный URL бакета")
# ВАЖНО: Указывайте ТОЛЬКО домен БЕЗ протокола (без https://)
AWS_S3_CUSTOM_DOMAIN=your-bucket-name.s3.beget.com

# Режим доступа (public или signed)
S3_FILE_ACCESS_MODE=public
```

### 2. Проверьте логи Django при запуске

При запуске Django сервера вы должны увидеть одно из сообщений:

**✅ Если S3 активирован:**
```
✅ S3 хранилище активировано: your-bucket-name
   Публичный URL: https://your-bucket-name.s3.beget.com/
```

**⚠️ Если S3 не активирован или параметры не указаны:**
```
⚠️ ВНИМАНИЕ: S3 хранилище активировано, но не указаны обязательные параметры!
   Установите в .env: AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_STORAGE_BUCKET_NAME
   Или установите USE_S3_STORAGE=0 для использования локального хранилища
```

или

```
ℹ️ Используется локальное хранилище (MEDIA_ROOT)
```

### 3. Проверьте настройки в панели Beget

1. Войдите в панель управления Beget
2. Перейдите в раздел **S3 хранилище**
3. Убедитесь, что бакет создан и активен
4. Проверьте **Реквизиты доступа**:
   - Access key
   - Secret key
   - Bucket name
   - Endpoint URL
   - Публичный URL бакета

### 4. Проверьте загрузку файла

1. Загрузите тестовый файл через админ-панель Django
2. Проверьте логи Django - не должно быть ошибок
3. Проверьте, что файл появился в S3 хранилище (через панель Beget или AWS CLI)
4. Проверьте URL файла - он должен начинаться с `https://your-bucket-name.s3.beget.com/` или `https://s3.beget.com/your-bucket-name/`

### 5. Проверьте, куда сохраняются файлы

**Если файлы сохраняются в S3:**
- URL файла будет начинаться с `https://your-bucket-name.s3.beget.com/` или `https://s3.beget.com/your-bucket-name/`
- Файл будет виден в панели Beget в разделе S3 хранилище
- Файл НЕ будет в директории `backend/media/` на сервере

**Если файлы сохраняются локально:**
- URL файла будет начинаться с `/media/`
- Файл будет в директории `backend/media/` на сервере
- Файл НЕ будет виден в панели Beget

## Исправление проблем

### Проблема: Файлы загружаются на локальный диск, а не в S3

**Решение:**

1. Проверьте, что `USE_S3_STORAGE=1` в файле `.env`
2. Проверьте, что все параметры S3 указаны правильно
3. Перезапустите Django сервер:
   ```bash
   sudo systemctl restart sofa-backend
   ```
4. Проверьте логи при запуске - должно быть сообщение об активации S3

### Проблема: Ошибка "S3 хранилище активировано, но не указаны обязательные параметры"

**Решение:**

1. Убедитесь, что в `.env` указаны все параметры:
   - `AWS_ACCESS_KEY_ID`
   - `AWS_SECRET_ACCESS_KEY`
   - `AWS_STORAGE_BUCKET_NAME`
2. Проверьте, что значения скопированы правильно (без лишних пробелов, кавычек)
3. Перезапустите Django сервер

### Проблема: Ошибка 403 при доступе к файлам

**Решение:**

1. Проверьте настройки CORS в панели Beget
2. Проверьте политику доступа к бакету
3. Если используете `S3_FILE_ACCESS_MODE=signed`, убедитесь, что файлы загружены с ACL `private`
4. Если используете `S3_FILE_ACCESS_MODE=public`, убедитесь, что файлы загружены с ACL `public-read`

### Проблема: Файлы не видны в панели Beget

**Решение:**

1. Проверьте, что бакет выбран правильно в настройках
2. Проверьте права доступа к бакету
3. Убедитесь, что файлы действительно загружаются (проверьте логи Django)
4. Попробуйте загрузить файл через админ-панель и сразу проверить в панели Beget

## Быстрая проверка

Выполните на сервере:

```bash
# Перейдите в директорию backend
cd ~/sofa-marketplace/backend

# Проверьте наличие .env файла
ls -la .env

# Проверьте настройки S3 (если файл существует)
grep USE_S3_STORAGE .env
grep AWS_ACCESS_KEY_ID .env
grep AWS_STORAGE_BUCKET_NAME .env

# Проверьте логи Django при запуске
sudo journalctl -u sofa-backend -n 50 | grep -i s3
```

## Важные замечания

1. **После изменения `.env` файла обязательно перезапустите Django сервер**
2. **Файлы, загруженные до активации S3, останутся на локальном диске**
3. **Для миграции существующих файлов в S3 используйте скрипт миграции или загрузите их заново**
4. **Убедитесь, что на сервере достаточно места для временного хранения файлов во время загрузки в S3**

## Проверка работы S3

После настройки выполните тестовую загрузку:

1. Войдите в админ-панель Django
2. Перейдите в **Catalog** → **Файловые ресурсы**
3. Загрузите тестовый файл
4. Проверьте URL файла - он должен начинаться с S3 URL
5. Проверьте наличие файла в панели Beget

Если все работает правильно, вы увидите файл в S3 хранилище, а не в локальной директории `media/`.
