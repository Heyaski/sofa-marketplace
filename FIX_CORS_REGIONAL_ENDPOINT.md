# 🔧 Исправление CORS ошибки для региональных endpoints Beget

## 🚨 Проблема

При загрузке 3D моделей из S3 хранилища Beget с региональным endpoint возникает ошибка CORS:

```
Access to fetch at 'https://s3.ru1.storage.beget.cloud/604ac302c572-joyful-valeriy/assets/...' 
from origin 'https://vizhub.pro' has been blocked by CORS policy: 
No 'Access-Control-Allow-Origin' header is present.
```

**Важно:** Файл скачивается при прямом переходе по ссылке, но не загружается через fetch/XMLHttpRequest из браузера.

## ✅ Решение: Настройка CORS в панели Beget

CORS настраивается на уровне бакета в панели управления Beget. Это обязательный шаг для работы с региональными endpoints.

### Шаг 1: Откройте настройки бакета в Beget

1. Войдите в [панель управления Beget](https://beget.com)
2. Перейдите в раздел **"Облако"** → **"Объектное хранилище"**
3. Выберите ваш бакет: `604ac302c572-joyful-valeriy`
4. Перейдите на вкладку **"Настройки"** выбранного бакета
5. Найдите раздел **"CORS"** или **"Настройки CORS"**
6. Нажмите **"Добавить"** или **"Редактировать"** (если правило уже существует)

### Шаг 2: Добавьте CORS правило

Заполните следующие параметры **точно**:

#### ⚠️ КРИТИЧЕСКИ ВАЖНО:

- **Allowed Origins (Разрешенные источники)**:
  - Укажите `https://vizhub.pro` (ваш домен, **БЕЗ слеша в конце!**)
  - ⚠️ **НЕ** используйте `https://vizhub.pro/` (со слешем)
  - ⚠️ **НЕ** используйте `vizhub.pro` (без протокола)
  - Если используете `www.vizhub.pro`, добавьте отдельное правило для него
  - Для тестирования можно временно использовать `*` (разрешает все домены, менее безопасно)

- **Allowed Methods (Разрешенные HTTP-методы)**:
  - ✅ **GET** (обязательно) - для загрузки файлов
  - ✅ **HEAD** (рекомендуется) - для получения метаданных
  - ⚠️ **OPTIONS** обычно обрабатывается автоматически сервером S3 для preflight запросов
  - Если в панели Beget есть возможность выбрать OPTIONS, выберите его тоже

- **Allowed Headers (Разрешенные заголовки)**:
  - Укажите `*` для разрешения всех заголовков (рекомендуется)
  - Или конкретные заголовки: `Authorization, Content-Type, x-amz-*`

- **Expose Headers (Открытые заголовки)**:
  - Можно оставить пустым
  - Или указать: `ETag, Content-Length, Content-Type`

- **Max Age Seconds (Максимальный возраст)**:
  - Укажите `3600` (1 час) - время кэширования результатов preflight-запросов

### Шаг 3: Сохраните настройки

1. Нажмите **"Сохранить"** или **"Применить"**
2. ⚠️ **Подождите 5-15 минут** - настройки CORS могут применяться с задержкой
3. Очистите кэш браузера или используйте режим инкогнито
4. Попробуйте загрузить файл снова

## 🔍 Проверка CORS

### Способ 1: Проверка в консоли браузера

1. Откройте консоль браузера (F12)
2. Перейдите на вкладку **Network**
3. Попробуйте загрузить 3D модель
4. Найдите запрос к файлу `.glb`
5. Откройте вкладку **Headers** в деталях запроса
6. Проверьте заголовки ответа:
   - ✅ Должен быть `Access-Control-Allow-Origin: https://vizhub.pro` (или `*`)
   - ✅ Должен быть `Access-Control-Allow-Methods: GET, HEAD` (или больше)
   - ❌ Если заголовков нет, значит CORS не настроен правильно

### Способ 2: Проверка через curl

Выполните в терминале:

```bash
curl -I -H "Origin: https://vizhub.pro" \
  "https://s3.ru1.storage.beget.cloud/604ac302c572-joyful-valeriy/assets/диванУ000010_FIElSex.glb"
```

В ответе должны быть заголовки:
```
Access-Control-Allow-Origin: https://vizhub.pro
Access-Control-Allow-Methods: GET, HEAD
```

### Способ 3: Проверка preflight запроса

1. Откройте консоль браузера (F12) → вкладка Network
2. Попробуйте загрузить 3D модель
3. Найдите запрос с методом **OPTIONS** (preflight запрос)
4. Он должен возвращать статус **200** или **204**
5. В заголовках ответа должны быть CORS заголовки

## 🚨 Если проблема сохраняется

### Вариант 1: Используйте wildcard для Origin (временно)

Для тестирования используйте `*` для Origin:

- **Origin**: `*`
- **Разрешенные HTTP-методы**: `GET, HEAD`
- **Разрешенные заголовки**: `*`
- **Время кэширования CORS**: `3600`

⚠️ **Внимание:** Это менее безопасно, но поможет проверить, работает ли CORS вообще.

### Вариант 2: Проверьте точность указания Origin

Убедитесь, что Origin указан **точно**:

- ✅ Правильно: `https://vizhub.pro` (без слеша)
- ❌ Неправильно: `https://vizhub.pro/` (со слешем)
- ❌ Неправильно: `vizhub.pro` (без протокола)
- ❌ Неправильно: `http://vizhub.pro` (HTTP вместо HTTPS)

### Вариант 3: Добавьте несколько правил CORS

Если используете несколько доменов, добавьте отдельные правила для каждого:

1. `https://vizhub.pro`
2. `https://www.vizhub.pro` (если используете)
3. `http://localhost:3000` (для разработки, если нужно)

### Вариант 4: Проверьте публичную политику доступа

1. В панели Beget откройте настройки бакета
2. Перейдите в **"Политики доступа"**
3. Убедитесь, что включена **"Публичная политика"**

### Вариант 5: Проверьте задержку применения настроек

CORS настройки могут применяться с задержкой:

1. Подождите **10-15 минут** после сохранения настроек
2. Очистите кэш браузера (Ctrl+Shift+Delete)
3. Используйте режим инкогнито
4. Попробуйте загрузить файл снова

## 📝 Дополнительная информация

### Почему CORS важен?

CORS (Cross-Origin Resource Sharing) - это механизм безопасности браузеров, который блокирует запросы между разными доменами. Когда ваш сайт `https://vizhub.pro` пытается загрузить файл с `https://s3.ru1.storage.beget.cloud`, браузер проверяет CORS заголовки.

### Как работает CORS для региональных endpoints?

- CORS настраивается на уровне бакета в панели Beget
- Настройки применяются ко всем запросам к бакету, независимо от формата URL
- Работает для всех типов запросов: GET, HEAD, OPTIONS
- Работает для всех форматов URL: path-style и virtual hosted style

### Важные моменты:

1. **CORS настройки применяются с задержкой** - подождите 5-15 минут после сохранения
2. **Origin должен быть указан точно** - без слеша, с правильным протоколом
3. **Метод OPTIONS обрабатывается автоматически** - не нужно настраивать отдельно
4. **CORS работает для всех запросов** - включая подписанные URL (если используете)

3. ❌ Настройки еще не применились (нужно подождать 5-15 минут)
4. ❌ Кэш браузера содержит старые данные

3. ✅ Укажите заголовки: `*`
4. ✅ Подождите 5-15 минут после сохранения
5. ✅ Очистите кэш браузера
