# 🔧 Исправление ошибки 403 при использовании подписанных URL

Если вы используете режим `S3_FILE_ACCESS_MODE=signed` и получаете ошибку 403, выполните следующие шаги:

## ✅ Шаг 1: Убедитесь, что файлы загружены с правильным ACL

**Важно:** Файлы, загруженные **до** переключения на режим `signed`, могут иметь публичный ACL и не будут работать с подписанными URL.

### Решение: Перезагрузите файлы

1. Откройте админ-панель Django
2. Перейдите в **Catalog** → **Файловые ресурсы**
3. Найдите файл, который выдает ошибку 403
4. **Удалите** его
5. **Загрузите файл заново**

Новые файлы будут автоматически загружены с ACL `private` и будут работать с подписанными URL.

## ✅ Шаг 2: Проверьте настройки в .env

Убедитесь, что в файле `.env` правильно указаны все параметры:

```bash
USE_S3_STORAGE=1
S3_FILE_ACCESS_MODE=signed
AWS_ACCESS_KEY_ID=your_access_key
AWS_SECRET_ACCESS_KEY=your_secret_key
AWS_STORAGE_BUCKET_NAME=your-bucket-name
AWS_S3_ENDPOINT_URL=https://s3.beget.com
AWS_S3_CUSTOM_DOMAIN=your-bucket.s3.beget.com  # БЕЗ https://
```

## ✅ Шаг 3: Не включайте публичную политику в Beget

**Важно:** При использовании режима `signed`:
- ❌ **НЕ включайте** публичную политику в настройках бакета Beget
- ✅ Файлы должны быть **приватными** в бакете
- ✅ Доступ только через подписанные URL, генерируемые Django

## ✅ Шаг 4: Проверьте формат URL

Подписанный URL должен содержать query параметры с подписью, например:

```
https://bucket.s3.beget.com/path/to/file.glb?AWSAccessKeyId=...&Expires=...&Signature=...
```

Если URL не содержит этих параметров, значит подписанный URL не генерируется правильно.

## ✅ Шаг 5: Перезапустите Django сервер

После изменения настроек обязательно перезапустите сервер:

```bash
python manage.py runserver
```

## 🔍 Проверка работы подписанных URL

1. Откройте API endpoint, который возвращает файлы (например, `/api/catalog/products/`)
2. Проверьте поле `file_url` в ответе
3. URL должен содержать query параметры с подписью
4. Скопируйте URL и откройте в браузере - файл должен загрузиться

## 🚨 Если проблема сохраняется

### Вариант 1: Используйте endpoint URL вместо custom domain

В некоторых случаях подписанные URL лучше работают с endpoint URL. В файле `.env`:

```bash
# Закомментируйте или удалите AWS_S3_CUSTOM_DOMAIN
# AWS_S3_CUSTOM_DOMAIN=your-bucket.s3.beget.com

# Используйте только endpoint URL
AWS_S3_ENDPOINT_URL=https://s3.beget.com
```

### Вариант 2: Переключитесь на публичный доступ (временно)

Если подписанные URL не работают, можно временно переключиться на публичный доступ:

```bash
# В файле .env
S3_FILE_ACCESS_MODE=public
```

И включите публичную политику в настройках бакета Beget.

## 📝 Дополнительная информация

- Подписанные URL действительны **1 час** (настраивается через `AWS_QUERYSTRING_EXPIRE`)
- После истечения срока URL становится недействительным
- Для получения нового URL нужно снова запросить файл через API
